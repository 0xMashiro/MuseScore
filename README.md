# Linked instrument-change keys after preceding-key edits

Verified 2026-09-08 on unmodified official main `a64e0d0c8725a89af2b4b9f8e058a75be20c01d3` and the attached `candidate.patch`.

Environment: Ubuntu 24.04.2, Qt 6.10.2, GCC 14, Debug/ASan, desktop GUI operated by a coding agent through Xvfb. Each video is 20 seconds. Audio/playback is not part of this verification.

## Reproduce

Extract `reproduction-scores.zip`. Each file has a flute changing to B-flat clarinet at measure 2 and an existing linked flute part. Keep Concert pitch off, as in the recordings. Open the existing flute part through Parts (the deletion fixture calls it Flute (1)). Do not create a new part.

### Change

Open `linked-key-change.mscz`, then the existing flute part. Select its first note and double-click G major (one sharp) in the Key signatures palette. The later To Clarinet key changes from two sharps to three in the part. Switch to the full score.

Before: the full score's opening key changes, but its To Clarinet key stays at two sharps. After: both linked copies show three sharps at the instrument change.

### Delete

Open `linked-key-delete.mscz`, then the existing Flute (1) part. Select the one-sharp key at beat 3 of measure 1 and press Delete. The part's later To Clarinet key changes from three sharps to two. Switch to the full score.

Before: the preceding key is deleted in both copies, but the full score's To Clarinet key still has three sharps. After: both copies correctly have two sharps.

Videos: `change-before.mp4`, `change-after.mp4`, `delete-before.mp4`, `delete-after.mp4`. All recordings use fresh copies of the matching input. `*-result.png` captures the full-score result. File origins: minimal score examples generated by the TypeScript port's timed-instrument workflow and independently loaded and edited in the native desktop and tests. This is not a claim that the initial files were authored through the desktop GUI.

## Candidate and native evidence

Apply `candidate.patch` to the baseline with `git apply candidate.patch`. It includes the two editing corrections, separate named native tests, and both fixtures with repository-relative paths.

The key-change loop calls the later-key update on each linked staff's owning score. The independent deletion path follows linked staves and invokes the same helper on their owning scores. The patch does not change global/local key policy or the helper's stopping rule at the next explicit key.

Build target: `engraving_tests`. Run from the native build's `src/engraving/tests` directory:

```sh
QT_QPA_PLATFORM=offscreen ASAN_OPTIONS=detect_leaks=0:new_delete_type_mismatch=0 ./engraving_tests --gtest_filter='Engraving_InstrumentChangeTests.*:Engraving_KeySigTests.*'
```

- Official production code plus new tests: 10 original tests pass; both new tests fail (`native-before.log`).
- Both candidate corrections: all 12 pass (`native-fixed.log`).
- New tests cover both initiating scores, key DOM and map agreement, undo, redo, integrity checks and production MSCZ save/reopen with the linked part.
- Applying only the key-change receiver correction passed the earlier change probe while leaving the delete probe failing. The two mutation paths require separate corrections.
- Official Uncrustify configuration and `git diff --check` pass.
